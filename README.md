# Codex Workbench

Codex Workbench is a self-hosted, browser-based, single-user interface in development for the
official OpenAI Codex app-server. The repository now contains the architecture, a productive
single-user authentication boundary, and version-exact capability contracts. It does **not** yet
start Codex or expose agent actions.

## Current implementation

- Async FastAPI backend with Pydantic 2 configuration, JSON logging, liveness/readiness probes,
  constrained repository discovery, path validation, and a fail-closed app-server transport
  boundary.
- One-time password setup with Argon2id, an external verifier file, keyed digest-only SQLite
  sessions, rotation/expiry/revocation, HttpOnly cookies, exact Origin and CSRF enforcement,
  login throttling, structured security events, and an authenticated WebSocket handshake boundary.
- React 19 / strict TypeScript / Vite frontend with Setup, Login, Session Expired, rate-limit,
  loading/error, Logout, and a protected responsive shell with keyboard focus management.
- Version-exact app-server TypeScript and JSON schemas generated by Codex CLI 0.146.0.
- Protocol-reviewed Workbench domain contracts for permissions, activity, normalized events,
  usage/rate limits, approvals, and uploads without a productive app-server connection.
- Non-root backend and frontend images, one externally published frontend service, internal backend
  network, persistent workspace/data/Codex-home mounts, healthchecks, and hardened defaults.
- Backend and frontend tests, linting, type checks, build commands, secret-pattern scanning, and
  repository hygiene.

The architecture and security model are in docs/architecture.md and docs/security-model.md. The
Codex capability matrix is in docs/app-server-capability-matrix.md. The scope boundary is in
docs/product-scope.md and staged delivery is in docs/implementation-roadmap.md.

## Prerequisites

For local development:

- Python 3.12 (the inspected host currently has Python 3.14.5, which can run the checks but is not the
  production target)
- Node.js 24 and npm 11
- OpenAI Codex CLI 0.146.0 for schema regeneration
- Docker with the Compose plugin only for container validation and deployment

No global project packages are required.

## Local development

Create project-local dependencies without requiring Make:

    ./scripts/bootstrap-backend.sh
    ./scripts/bootstrap-frontend.sh

`make bootstrap` is the equivalent convenience target when Make is installed.

Run the backend:

    cd backend
    .venv/bin/uvicorn codex_workbench.main:app --reload --host 127.0.0.1 --port 8000

Run the frontend in another terminal:

    cd frontend
    npm run dev

Vite listens on 127.0.0.1:5173 and proxies /api to the local backend. See docs/development.md for
the required local session-key/state initialization, explicit HTTP development settings, and
individual commands.

## Verification

Run every available check without requiring Make:

    ./scripts/verify.sh

`make verify` is the equivalent convenience target when Make is installed.

Verification includes backend/frontend linting, strict typing, tests, the frontend production
build, a secret-pattern scan, Python/npm dependency audits, and `git diff --check`.

Docker configuration can additionally be checked where Docker exists:

    cp .env.example .env
    # Set CODEX_HOME_PATH to an existing directory.
    docker compose config --quiet

The current execution environment has no Docker binary, so image and Compose runtime validation
must be performed on a Docker-capable host.

## Deployment preparation

The initialization script creates ignored persistent directories, a local `.env` copy, and a
random session-key file; it does not create a password and does not start containers:

    ./scripts/init-deployment.sh

Review docs/deployment.md before using Compose. Setup is completed through the first-start page.
The deployment still keeps `WORKBENCH_APP_SERVER_START_ENABLED=false`; it is authenticated but not
yet capable of agent work.

## Schemas

The checked-in app-server schemas are generated artifacts. Their version, commands, and update
procedure are documented in schemas/codex-app-server/GENERATED.md and
docs/app-server-integration.md. Generated files are protocol authority but never browser DTOs.
